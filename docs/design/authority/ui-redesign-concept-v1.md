# Triangulum Daily UI Redesign Concept — Formal v1

状态：**当前产品概念 authority**
生效日期：2026-08-30

## 1. 产品意图

Triangulum Daily 每个自然日发布 9 张完整专辑，分三次解锁。产品价值不是随机动画本身，也不是复古皮肤，而是让用户在一个有限、可理解的每日收藏中遇见完整专辑，获得可信背景和推荐理由，并决定去哪里继续探索。

推荐和数据仍在构建期产生；浏览器消费静态 JSON 与静态资产。产品不要求账户、评论、播放器、访客写入、运行时音乐数据 API 或新后端。

## 2. 核心隐喻

唯一核心隐喻是：**进入一家微缩唱片店，像处理实体唱片一样浏览当天有限库存。**

空间链由两部分组成：

- 持久存在、以六个 preset view 为构图锚点并支持受限自由观察与缩放的三维 Entry Diorama；
- 点击实体大门后进入的 Public Record Gallery 店内。

店外和店内是同一家店的连续身份，但不是互相强迫复制的平面图。店外负责到达、建筑存在感和门槛；店内负责设备、唱片浏览、阅读和最近历史日期。

## 3. 为什么采用这种结构

- 六个 preset view 保留被设计过的构图和可验证几何；受限自由观察只用于近距离检查同一完整微缩世界。
- 实体门把空间探索和进入行为绑定到同一个可见对象。
- 店内固定母场景让唱片、装置、HUD 和阅读状态能稳定变化，不被自由相机破坏。
- 同一唱片从书脊变成封面和阅读对象，保持对象连续性，避免卡片墙、dashboard 或无关详情页。
- 3／6／9 张唱片构成一天逐步增长的同一库存，而不是三组彼此割裂的页面。

## 4. 产品世界中的角色

### Entry Diorama

是 Today Page 的到达状态。它不是开场动画、普通街道或可无限漫游的游戏场景。建筑从一开始就存在；六个 preset view 提供稳定构图，指针或触控只可在受限范围内检查同一建筑。

### 实体大门

是店外与店内的唯一规范边界。门必须在视觉上真实、在交互上明确、在无障碍层面可命名。

### Public Record Gallery

是店内主空间。中央装置承担 Daily OPEN、Shuffle、水平库存和唱片打开；HUD 承担日期、BJT 时间、设备与库存状态；Treatment Viewer 承担深度阅读。

### 店员

店员是稳定的人物身份和空间尺度锚点。她不是聊天机器人、任务发布者、吉祥物或内容替代品。店内使用批准的吧台专用放松姿势，双手由吧台平面自然支撑；店外可使用批准的吸烟等生活姿势，但任何姿势都不能改变身份。

## 5. 每日节奏

一天的库存按 BJT 从 0 扩展到 3、6、9。Daily OPEN 与 Shuffle 是当前店内会话中的进入仪式；同一会话里的新时段只向同一库存追加唱片。

具体时间、Skip 条件、持久化和状态迁移由交互规范定义，本文不重复。

## 6. 浏览与阅读

唱片以竖立书脊组成有限的水平序列。用户通过拖动、方向控制或键盘移动，并以临时 hover／focus 了解当前对象。

激活唱片时，同一对象转为 Treatment Viewer 中的正方形封面与阅读内容。返回后恢复原水平位置，但不保留临时选中。阅读内容以可靠元数据、推荐上下文和有效外部路径为核心，不伪造未审核的专辑事实。

## 7. 历史关系

店内 HUD 提供有限的最近日期切换，让用户在同一空间和装置中查看已完成日期的 9 张唱片。站点级 Archive Page 仍可提供更广历史范围，但它不是另一间房，也不创造另一套产品隐喻。

## 8. 明确废止的方向

下列方向不再属于当前概念：

- 普通街道、建筑分开、店铺显现的旧入口序列；
- 无边界自由轨道、第一人称或任意角度的店外漫游；
- 店外模型强行一比一复制店内平面图；
- 3×3 固定卡片墙、九宫格主界面或三套独立时段页面；
- 将未来 Today 唱片提前显示为锁定物；
- 把 Archive 解释成另一间房、黑色空间、资料库或控制室；
- 将 Treatment 变成独立详情路由；
- 用通用 dashboard、Coverflow 页面、抽卡或牌组替代唱片店装置；
- 把人物作为聊天入口、悬浮头像或主要内容区；
- 通过全局发黄、数字涟漪、脏纹或无来源霓虹制造所谓氛围。

## 9. Authority 分工

- [`authority/`](./README.md) 决定批准资产及店外／店内／人物关系。
- [`ui-visual-interaction-system.md`](./ui-visual-interaction-system.md) 决定视觉、材质、构图、状态外观、动效气质和验收门槛。
- [`Triangulum-Daily-UI-Interaction-Specification-v1.md`](./Triangulum-Daily-UI-Interaction-Specification-v1.md) 决定时间、输入、状态、迁移、返回和持久化。
- 本文只决定产品目标、核心隐喻、体验结构和废止方向。

工程实现必须遵守静态 GitHub Pages 架构、构建期数据获取、浏览器运行时数据隔离、BJT 产品时钟和现有公共 JSON 边界；这些不由视觉重设计改变。
