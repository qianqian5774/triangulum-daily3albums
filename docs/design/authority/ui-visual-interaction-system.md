# Triangulum Daily 正式视觉与视觉交互系统

版本：Formal 1.0
状态：**当前视觉 authority**
生效日期：2026-08-30

## 1. 文档职责与权威顺序

本文定义 Triangulum Daily 的视觉世界、空间表达、材质、构图、界面层级、状态外观、动效气质、响应式原则和视觉验收门槛。它不重复产品逻辑、时间计算或持久化细节。

发生冲突时，按以下顺序处理：

1. [`authority/`](./README.md) 及其内部 manifest 决定已批准资产和空间关系。
2. 本文决定这些资产如何构成正式视觉系统。
3. [`Triangulum-Daily-UI-Interaction-Specification-v1.md`](./Triangulum-Daily-UI-Interaction-Specification-v1.md) 决定状态、输入、时间和迁移。
4. [`ui-redesign-concept-v1.md`](./ui-redesign-concept-v1.md) 解释产品意图，不覆盖前述可执行规范。

历史概念、拒绝稿、旧店员、旧入口序列及 `_archive/` 下的内容没有当前 authority。

## 2. 唯一总体视觉模型

Triangulum Daily 是一个由两个连续空间状态组成的网页唱片店：

- **店外：**持久存在的 Entry Diorama，以真实三维模型呈现；六个 preset view 提供构图锚点，指针或触控可在受限范围内检查同一模型。
- **店内：**Public Record Gallery，以已批准 FRAME 04–14 的分层合成画面呈现；装置、唱片、HUD 和阅读界面在同一店内世界中改变状态。
- **边界：**店外实体大门是进入店内的唯一标准入口。进入不是新页面视觉风格的切换，而是跨过同一家店的门槛。

店外模型不要求一比一复制店内平面图。两者通过店名、黑框玻璃入口、唱片库存、中央 CRT／试听装置、珊瑚红吧台、白桦木／石墨黑材质和同一店员建立身份连续性。

## 4. 店外三维场景系统

### 4.1 构图与相机

- 默认是横向 16:9 的微缩建筑展示构图，店体与完整正方形基座必须同时可读。
- 六个预先批准的 preset view 是正式构图锚点。指针或触控可在受限的 yaw、pitch 与 zoom 范围内检查模型；不允许无边界轨道、第一人称漫游、鱼眼或广角漂移。
- 同一组平行边应保持稳定，直立线保持垂直；相机变化不能使门、屋顶或基座比例看似改变。
- 每个视角必须保留明确的到达区与可辨识大门。门不能被道具、人物、招牌或相机裁切遮蔽。
- 切换视角只揭示已有结构，不重排物体、不替换材质、不偷偷修补几何。

### 4.2 建筑与物理完整性

- 基座是真正的 1:1 正方形，铺地连续，裙边等厚，所有人物和道具落在安全内缩范围内。
- 平屋顶是连续完整实体；女儿墙、压顶、设备基座与屋面接缝必须有可信支撑和排布。
- 外立面必须有清楚的墙体厚度、门窗洞口、门框支点、玻璃边界、檐口与转角收口。
- 黑框玻璃入口必须读成可开启的大门，而不是无玻璃缺口、悬空钢条或装饰内门。
- 任何栏杆、圆形装饰、招牌支架、雨棚或灯具都必须有可追踪支撑点；禁止穿墙、悬空、相交或跨壳体连接。
- 室内唱片箱不得无理由出现在外立面成为杂物。外摆物只能是有明确商业用途和尺度的陈列、座椅、烟灰缸、植物或营业信息。

### 4.3 玻璃与材质

- 玻璃必须同时表现透明度、轻微反射、边缘厚度和后方可见内容；不能像空洞，也不能像不透明蓝板。
- 石墨黑金属以低至中等粗糙度表现，边缘有克制高光，不使用纯黑吞没结构。
- 白桦木保留浅色木纹和结构方向；珊瑚红只承担柜台、局部面板或识别锚点，不泛化为全场滤镜。
- 屋面和大面积平面必须干净、连续、低噪声。任何重复波纹、等高线状纹理、脏斑、伪压花或数字涟漪都直接判失败。
- 微缩模型感来自真实尺度、倒角、接触阴影、材质分离与克制景深，不来自全局发黄、统一噪点或滤镜。

### 4.4 外立面信息密度

外立面应具备正常商家的必要识别和使用痕迹，但不能堆满道具：

- 清晰且拼写正确的 `TRIANGULUM DAILY` 店名；
- 可理解的门把、门槛、营业／入口信息位；
- 有支撑的檐口、雨棚或灯具；
- 克制的植物、烟灰缸或营业陈列；
- 屋面设备、检修边界和合理基座；
- 门前通行宽度和无遮挡的入口路径。

不存在的构件不应仅为了“丰富细节”被添加；每件物体都必须有用途、位置和尺度解释。

## 5. 店内 Public Record Gallery 系统

### 5.1 固定空间

FRAME 04–14 共享同一 1680×945 店内母场景。下列内容固定：

- 左侧黑框玻璃门和外部时间光线；
- 背墙唱片库存与标签；
- 中央 CRT／试听装置；
- 右侧白桦木与珊瑚红吧台；
- 吧台后的批准店员；
- 顶部 HUD 的空间位置。

除状态所需的屏幕、HUD、唱片、阅读或光照变化外，不得移动货架、改墙面、换吧台、增删海报或改变透视。

### 5.2 分层顺序

店内正式合成顺序为：

1. 日间或夜间环境母图；
2. 在线状态的屏幕背光；
3. 被玻璃遮罩约束的动态屏幕内容；
4. 永久内压边框；
5. 独立 RGBA 店员层；
6. HUD 壳体；
7. 状态文字和临时交互层。

必要状态和操作必须是可访问的真实界面层，不能永久烘焙进环境图。生成图只提供受控视觉表面，不承担状态逻辑。

### 5.3 店员

- 唯一人物身份由批准四视图锁定：黑色短波波头、白／银前发束、琥珀色眼镜、金色圈耳环、黑色无袖上衣、黑腰带、深色低饱和宽腿牛仔裤和黑色低帮鞋。
- 室内使用批准的吧台专用放松姿势：轻微重心偏移、双手分别由同一吧台平面支撑，不在店内吸烟。吧台自然遮挡下半身，人物层不能覆盖珊瑚前板。
- 人物必须有透明通道，边缘不能保留灰底、绿色溢色、棋盘格或矩形背景。
- 人物可以随昼夜做受控明度和色温处理，但脸、发束、眼镜和服装仍须可读。
- 店员是空间尺度与生命感锚点，不是聊天机器人、吉祥物、悬浮头像或主要内容区。

## 6. 信息与交互视觉层级

从高到低的操作优先级为：

1. 当前唱片或 Treatment Viewer；
2. 中央装置的当前任务；
3. HUD 的日期、时间、设备与库存状态；
4. 店员和可见库存；
5. 环境细节。

每个状态只能有一个主要操作焦点。视觉强调必须附着于真实对象：门、装置屏幕、唱片书脊、日期控件或阅读面板。禁止用无来源的全屏发光、全局暗幕或随机动效代替层级。

### 6.1 HUD

- HUD 只在店内出现，固定显示产品日期、BJT 时间、设备状态和必要库存信息。
- HUD 是高对比石墨硬件表面，不是浏览器顶部导航栏的伪装。
- 日期菜单属于 HUD 同层，必须从日期控件建立明确空间关系。
- 状态不能只靠颜色表达；文字、形状和固定位置必须共同说明 OFFLINE、READY、ON、历史日期等状态。

### 6.2 装置与唱片

- 装置屏幕内容被物理玻璃和压边框约束，不能变成覆盖整台设备的网页卡片。
- 唱片在浏览状态以竖立书脊组成有限水平库存；相邻唱片保持可感知，但当前对象最清楚。
- hover／focus 只产生克制位移、边缘或亮度变化，不产生永久选择状态。
- 打开唱片时，同一物件从书脊转为正方形封面和阅读对象；不得突然替换成无关卡片页面。

### 6.3 Treatment Viewer

- Treatment Viewer 是覆盖层，不是独立路由。
- 店内仍可辨识，但对比度和细节退后；当前唱片、标题、艺人、可靠元数据、推荐上下文和有效外链成为主层。
- 阅读文本使用正常可读字体与行宽，不伪装成 CRT、像素字或唱片封面的一部分。
- 关闭后恢复先前水平位置，但清除临时 hover／selection。

## 7. 色彩与排版

### 7.1 核心色彩关系

| 角色 | 建议值 | 用途 |
| --- | --- | --- |
| Graphite | `#202427` / `#2b2a27` | 金属框、装置外壳、HUD、正文深色 |
| Ivory | `#f3f1e9` | 墙面、阅读底、亮部 |
| Birch | `#d8bd91` | 木质货架、柜体、设备台面 |
| Coral | `#be4e39` | 吧台识别面、受控主要操作 |
| Amber | `#dca14e` | 实体灯、ready/focus 的局部强调 |
| Sage field | `#e7eee5` 附近 | 店外背景场，不作为大段正文底色 |
| Cool night | `#17212a` 附近 | 夜间环境凹部，需保留层次 |

颜色值是生产锚点，不要求每个像素机械一致。强调色必须局部、有对象归属并满足对比度；珊瑚红和琥珀色不能成为永久全屏色洗。

### 7.2 字体职责

- **Reading sans：**正文、唱片信息、按钮和可访问标签。
- **Condensed display：**短店名、短状态标题和装置铭牌。
- **Monospace/system：**BJT 时间、日期、库存数和硬件状态。

正文不得使用伪像素字、全大写中文或过窄字形。正文目标行长约 24–34 个汉字；系统字只用于短信息。

## 8. 动效语言

- 相机视角变化：稳定、受控地从一个批准视角过渡到另一个批准视角；不允许惯性失控或视角越界。
- 门槛过渡：由门和空间边界承担，明确“进入”，避免炫技式隧道、街道显现或凭空生成店铺。
- 装置唤醒：背光、状态字和物理屏幕由暗到亮，层次有先后。
- Shuffle：是短暂、可跳过条件受规范约束的仪式；结束后必须回到安静店内层级。
- 唱片打开：对象连续变形，从书脊到封面／阅读，不凭空换对象。
- reduced motion：移除大范围相机和旋转，保留直接淡入、状态替换、focus 及完整操作结果。

动效参数和触发条件由交互规范负责；本文只规定视觉连续性和禁止项。

## 9. 响应式与无障碍

- 小屏不改变产品状态机。六个 preset view 与受限观察范围保持一致；不得因触控变成无边界自由漫游。
- 店外模型必须在安全画框内完整显示，入口和视角控件保持可用；必要时缩放整体，不裁掉门或基座。
- 店内优先保留装置、当前唱片、HUD 关键信息和返回控制；环境可裁切，但不能导致状态来源不明。
- 所有热点都要有键盘可达的语义控件、可见 focus、可读名称和足够点击区域。
- 颜色之外必须有文字／图标／几何冗余；正文对比度目标不低于 4.5:1。
- 透明、反射、纹理和夜间调色不能降低必要文字或焦点可见性。

## 10. 严格视觉验收门槛

任何候选出现以下任一问题即失败，不能用“总体不错”覆盖：

- 与冻结母版在建筑、比例、人物身份或空间地标上漂移；
- 屋顶洞、缺口、异常凸起、数字涟漪、重复脏纹或整体发黄；
- 玻璃缺失、过度不透明、无厚度或反射与透视不一致；
- 门框、栏杆、支架、圆环、招牌或雨棚悬空、穿墙、相交；
- 基座非正方形、铺地断裂、道具或人物落在基座外；
- 不明杂物、室内唱片箱误放室外、无用途装饰或入口被堵；
- 人物缺肢、比例漂移、抠图底色、Alpha 缺失或鞋底／吧台遮挡错误；
- 必要状态烧进背景、点击目标与可见对象不一致、focus 不可见；
- 新状态改变店内非状态区域或破坏已批准母图。

验收顺序固定为：资产哈希／结构验证 → 原生像素局部检查 → 全图空间与层级检查 → 多状态一致性检查 → 响应式和可访问性检查。数值通过不等于用户视觉批准。
